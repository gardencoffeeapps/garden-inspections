# Garden как веб-приложение

Выбранный вариант для пилота — **PWA**, веб-приложение с иконкой на телефоне. App Store, Google Play и аккаунты разработчиков Apple/Google для него не нужны. Вся логика обходов остаётся прежней; содержание чек-листа не изменено.

## Как будут пользоваться управляющие

1. Открывают общую защищённую ссылку Garden.
2. Входят под своей учётной записью.
3. При желании добавляют иконку на главный экран. Можно работать и в обычной вкладке.
4. Разрешают доступ к камере при первом снимке.
5. Выполняют обход и отправляют результат. Руководитель видит его по той же ссылке в своём аккаунте.

**iPhone:** Safari → «Поделиться» → «На экран Домой». Если браузер предлагает открывать как веб-приложение, оставьте этот вариант включённым.

**Android:** Chrome → меню ⋮ → «Установить приложение» или «Добавить на главный экран». Если браузер поддерживает предложение установки, внутри Garden появится кнопка «Добавить Garden на устройство». Названия пунктов могут отличаться в зависимости от версии браузера.

Доступ к камере выполняется внутри страницы через браузерный видеопоток. Кнопки выбора изображения из галереи нет. Браузер и ОС запрашивают разрешение на камеру. Работу реальных камер необходимо проверить на телефонах управляющих; криптографическая аттестация снимка не реализована.

## Что уже добавлено

- Манифест установки, русское название, иконки 192/512 px и иконка для iPhone.
- Отдельное окно без обычной адресной строки в поддерживаемых браузерах.
- Инструкции установки и кнопка установки там, где браузер её поддерживает.
- Сообщение об отсутствии сети.
- Кеширование только публичной оболочки: экранов, скриптов и иконок. Пароли, сессии, API-ответы и фотографии не попадают в кеш service worker.
- Обновления не перезагружают активный обход автоматически. Новая версия применяется после закрытия всех окон Garden и следующего запуска.

Сессия веб-версии хранится в sessionStorage и действует на сервере 12 часов. После закрытия приложения браузер может потребовать повторного входа. Уже сохранённый черновик остаётся на сервере.

## Интернет и камера

В этом прототипе **для обхода нужен интернет**. Кеш оболочки не означает автономное сохранение ответов или фото. Если сеть исчезла, дождитесь восстановления и повторите сохранение текущего шага. Не закрывайте страницу с несохранённым шагом.

Рабочая ссылка должна быть **HTTPS**. На компьютере `http://127.0.0.1:8787` подходит для разработки, но это не общедоступная ссылка для телефонов. Ввод того же адреса на телефоне обращается к самому телефону. Открытие IP компьютера по HTTP не обеспечивает работу камеры/PWA на мобильном устройстве.

## Размещение

Публикация на внешний сервер ещё не выполнена: домен и инфраструктура не предоставлены. Приложение работает локально на компьютере пользователя.

Для веб-пилота нужен один сервер с Node.js 24 и постоянным диском, домен/поддомен и HTTPS-прокси. Сервер Garden одновременно отдаёт интерфейс из `dist/` и API из `/api/`; отдельное размещение интерфейса не требуется.

Последовательность развёртывания:

1. Выбрать домен, например собственный поддомен компании, и сервер. Примерное имя не является созданным адресом.
2. Загрузить проект, собрать `pnpm build:web` или использовать готовый `dist/` из архива.
3. Запускать `node server/index.mjs` как постоянный сервис на `127.0.0.1:8787` за HTTPS-прокси.
4. Добавить фактический HTTPS-origin в `GARDEN_ALLOWED_ORIGINS`. Прокси должен передавать пути `/api/`, `/sw.js`, `/manifest.webmanifest`, `/icons/` и остальные статические файлы без изменения. Не переписывать ошибки API на HTML.
5. Хранить `server/data/` на постоянном диске и настроить резервное копирование SQLite вместе с фотографиями. Не заменять эту папку при обновлении кода.
6. Заменить учебные учётные записи персональными, настроить реальные кофейни и назначенных управляющих, проверить доступы. Публичное развёртывание с известными учебными паролями не подходит для рабочих данных.
7. Проверить установку, настоящую камеру и полный обход на Android и iPhone, затем выдать сотрудникам одну HTTPS-ссылку.

Сборка для веба по умолчанию использует API с того же адреса. Не задавайте `EXPO_PUBLIC_API_URL` на демонстрационный адрес из `.env.example`, если интерфейс и API размещаются вместе. Для корневого пути `/` настроены манифест и service worker; размещение в подпапке потребует изменения этих путей.

Документация: [устанавливаемые PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [установка веб-приложений](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Installing).
