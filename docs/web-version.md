# Garden как веб-приложение без сервера

Выбранный вариант для пилота — **PWA по одной ссылке**. Управляющим не нужны App Store, Google Play и установка из магазинов: они открывают ссылку Garden на рабочем телефоне и при желании добавляют её на главный экран.

Плановая ссылка после публикации GitHub Pages:

```text
https://gardencoffeeapps.github.io/garden-inspections/
```

## Как будут пользоваться управляющие

1. Открывают защищённую ссылку Garden.
2. Входят под своей учётной записью.
3. Разрешают камеру при первом обязательном фото.
4. Выполняют обход кофейни.
5. Завершают аудит; результат фиксируется на этом устройстве с автором и временем.

**iPhone:** Safari → «Поделиться» → «На экран Домой».

**Android:** Chrome → меню ⋮ → «Установить приложение» или «Добавить на главный экран».

## Что хранится

Данные сохраняются в `localStorage` браузера на телефоне:

- пользователь, который вошёл в приложение;
- черновики обходов;
- завершённые обходы;
- ответы, комментарии, дата начала и окончания;
- фотографии обязательных точек.

Если очистить данные сайта, сменить телефон или открыть ссылку на другом устройстве, локальные результаты там не появятся. Это нормальное ограничение варианта без сервера.

## Авторизация

Авторизация нужна, чтобы каждый аудит имел автора. В текущем MVP пользователи заданы в `src/api.ts`:

- `andrey` — управляющий кофейни «Свердлова»;
- `admin` — руководитель, видит результаты на текущем устройстве.

Это практичная авторизация для пилота, но не защита уровня корпоративной системы: список пользователей находится в коде веб-приложения. Для строгой безопасности и общего кабинета по всем телефонам нужен сервер или внешний сервис авторизации.

## Интернет и камера

После загрузки приложение может сохранять ответы локально, но рабочая ссылка всё равно должна открываться по HTTPS. Камера на телефонах в браузере обычно доступна только на HTTPS-страницах. GitHub Pages даёт HTTPS автоматически.

## Размещение

В репозитории добавлен workflow `.github/workflows/pages.yml`. Он собирает `dist/` и публикует его в GitHub Pages после каждого push в `main`.

Если Pages ещё не активен, откройте Settings → Pages и выберите источник **GitHub Actions**. После успешного запуска Actions ссылка появится в настройках Pages и в шаге deploy.

## Ограничения варианта без сервера

- Нет автоматического общего кабинета со всех телефонов.
- Нет централизованных резервных копий.
- Руководитель видит только данные на устройстве, где они сохранены.
- Для общей истории сети позже нужен сервер, Google Sheet/Form, Airtable, Supabase или другой общий приёмник результатов.
