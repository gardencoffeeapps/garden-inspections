# Garden · первый рабочий прототип

**Основной вариант теперь — веб-приложение PWA, без App Store и Google Play.** Управляющие открывают одну HTTPS-ссылку и добавляют Garden на главный экран. Руководитель использует ту же ссылку на компьютере. [Установка и размещение веб-версии](docs/web-version.md).

Веб-приложение для периодического управленческого обхода кофеен. Актуальная редакция: 23 сентября 2026 года. В комплекте: исходники Android/iOS, работающая веб-версия для просмотра, сервер, база данных и проверки.

## Запуск из GitHub

Установите Node.js 24 и pnpm 11, скачайте или клонируйте репозиторий. В папке проекта выполните:

```sh
pnpm install --frozen-lockfile
pnpm build:web
pnpm server
```

Откройте http://127.0.0.1:8787. Каталог `dist/` генерируется сборкой и не хранится в GitHub. Готовый архив Garden-MVP.zip включает `dist/`.

## Запуск из готового архива

Откройте PowerShell в папке распакованного проекта и выполните:

```powershell
./Start-Garden.ps1
```

Оставьте окно сервера открытым и перейдите по адресу выше. Веб-версия уже собрана в `dist/`; для её запуска достаточно Node.js 24. На этом компьютере сценарий также находит встроенный в Codex Node.js.

Тестовые учётные записи (перед внешним пилотом заменить временные пароли):

| Роль | Логин | Пароль | Доступ |
|---|---|---|---|
| Андрей, кофейня «Свердлова» | `andrey` | `Garden-demo-2026!` | Свердлова, свои обходы |
| Управляющий · демо | `manager` | `Garden-demo-2026!` | Обе учебные точки, свои обходы |
| Второй управляющий | `manager2` | `Garden-demo-2026!` | Учебная точка 2, свои обходы |
| Руководитель | `admin` | `Garden-demo-2026!` | Все точки и обходы, чтение |

Добавлена реальная кофейня «Свердлова» и управляющий Андрей, но пароль пока тестовый. Две учебные точки и их аккаунты сохранены для проверок; Андрей их не видит. В локальной базе после проверки интерфейса оставлен учебный черновик с одним комментарием о кофемашине. В архив проекта база и сессии не включены: при первом запуске создаётся чистая база.

## Что реализовано

- Вход под пользователем и выбор назначенной ему кофейни.
- 12 разделов, **136 исходных вопросов**, **10 обязательных фото**. Тексты перенесены дословно из последней полной редакции диалога. Ранее указанное в диалоге число «около 120» не совпадает с количеством строк; вопросы не сокращались.
- Единый стандартный чек-лист для всех кофеен: все 136 вопросов, включая весь раздел оборудования. Список оборудования не запрашивается, вопросы по точкам не фильтруются.
- Ответы «Да/Нет», обязательный непустой комментарий при «Нет». Максимум 2000 символов.
- Камера через Expo Camera, без выбора файлов из галереи. Фото требуется при любом ответе на отмеченный вопрос; на остальные вопросы фото не запрашивается.
- Кнопка «Сохранить и дальше» сохраняет шаг на сервере. После повторного входа можно продолжить тот же черновик. Несохранённый текущий шаг при выходе из него не сохраняется.
- Прогресс по каждому разделу; перед отправкой — только нарушения, комментарии и наличие обязательных фото.
- Сервер проверяет полноту заново, фиксирует время начала и окончания, автора, версию чек-листа и контрольную сумму результата с хешами фото.
- Отправка повторным запросом не создаёт дубль. После отправки изменение и удаление результата, замена фото запрещены сервером и триггерами базы. Журнал начала и отправки доступен через API.
- Кабинет руководителя: фильтр по кофейне, история, количество завершённых обходов/черновиков/нарушений, подробности и фотографии. Незавершённые обходы просматриваются без редактирования.

## Почему этот стек

**Expo SDK 57 + React Native + TypeScript** — общие экраны и логика для Android и iOS, доступ к камере через штатный компонент. Веб-сборка позволяет быстро посмотреть прототип на компьютере и использовать управленческий просмотр.

**Node.js 24 + SQLite** — один небольшой сервер без внешних аккаунтов и платных услуг. Телефоны работают с одним сервером, а не хранят раздельные отчёты. SQLite подходит для ограниченного пилота с одним серверным процессом. При росте сети можно перейти на PostgreSQL и объектное хранилище фото, сохранив API.

Документация: [Expo Camera](https://docs.expo.dev/versions/latest/sdk/camera/), [создание проектов Expo](https://docs.expo.dev/get-started/create-a-project/).

## Запуск на Android/iOS для теста

1. На компьютере разработчика установите Node.js 24 и pnpm 11. В папке проекта выполните `pnpm install --frozen-lockfile`.
2. Для реального пилота предоставьте приложению HTTPS-адрес сервера. Для локального теста через Expo Go компьютер и телефон должны видеть друг друга в одной сети. Запустите `./Start-Garden.ps1 -Lan`. Это явным образом разрешит серверу слушать сетевые интерфейсы; может потребоваться правило брандмауэра для порта 8787.
3. Запустите `pnpm start`, откройте проект в совместимой версии Expo Go на Android/iOS по показанному адресу/QR-коду.
4. На экране входа приложения нажмите «Настроить адрес сервера» и укажите `http://<IP-компьютера>:8787` для локального теста или HTTPS-адрес для защищённого соединения. `localhost` на телефоне означает сам телефон. Ограничения сети/HTTP у конкретного устройства могут потребовать HTTPS и в тесте.
5. Войдите в учебный аккаунт и разрешите камеру при первом фото. Проверьте настоящую съёмку, отправку и просмотр фото со второго устройства.

Веб-камера в браузере работает на `localhost` либо через HTTPS. Открытие браузерной версии на телефоне по обычному HTTP-адресу компьютера не заменяет тест нативного приложения.

### Необязательный альтернативный путь: отдельные нативные приложения

Подготовлен `eas.json`: профиль `preview` для внутренней установки, Android — APK. Выпуск через EAS требует аккаунта Expo, окончательных идентификаторов приложений и настроенного HTTPS API. Для iOS необходимы подпись и подходящий способ распространения Apple (например, TestFlight или зарегистрированные тестовые устройства). Эти аккаунты в задаче не предоставлялись: **подписанные APK/IPA не создавались, на телефоны приложение ещё не установлено**.

Перед сборкой задайте `EXPO_PUBLIC_API_URL` на адрес сервера. Идентификаторы `com.garden.inspections` пока являются проектными значениями, их доступность в магазинах не подтверждена.

## Проверка и разработка

```sh
pnpm test
pnpm typecheck
pnpm build:web
pnpm start
```

`pnpm server` запускает сервер. Веб-версия, собранная в `dist/`, обслуживается этим же сервером. `pnpm web` запускает интерфейс для разработки на 8081; API при этом должен работать на 8787. Для веб-разработки используется разрешённый origin `http://localhost:8081`.

Серверные настройки: `HOST` (по умолчанию `127.0.0.1`), `PORT` (8787), `GARDEN_ALLOWED_ORIGINS` (список через запятую), `GARDEN_DEMO_PASSWORD` (пароль только для **первого создания** учебных аккаунтов; не меняет существующие пароли). Сервер читает переменные окружения процесса; `.env` автоматически используется Expo, но не сервером.

## Структура проекта

```text
App.tsx                   Экраны управляющего и руководителя
src/api.ts                API, сессия, обработка сетевых ошибок
src/types.ts              Модели данных
shared/checklist.json     Версионированный согласованный чек-лист
shared/cafes.json         Кофейня Свердлова и учебные точки
server/index.mjs          API, авторизация, SQLite, защита отправленных данных
server/domain.mjs         Снимок единого чек-листа, валидация, контрольная сумма
tests/workflow.test.mjs   Проверки правил и полного серверного сценария
docs/checklist-source.md  Исходная согласованная редакция из диалога
docs/verification.md      Результаты проверки и ограничения
dist/                     Готовая веб-сборка
eas.json                  Профили будущих мобильных сборок
```

При первом запуске `shared/cafes.json` переносится в базу. Дальнейшая правка JSON не заменяет уже существующие точки автоматически. Изменение справочника реальных точек нужно оформить отдельным администраторским действием/миграцией; оно не должно менять снимки уже начатых обходов.

## Границы первого прототипа и следующий шаг

Прототип требует связи с сервером; автономной очереди и фоновой синхронизации пока нет. Фото сохраняются как JPEG в SQLite, максимум 5 МБ на снимок. Сервер декодирует JPEG, отклоняет повреждённые изображения и стороны меньше 240 px. Для этого включён исходный пакет jpeg-js 0.4.4 в `server/vendor/jpeg-js` с лицензиями; он входит и в архив, поэтому для запуска собранной веб-версии достаточно Node.js. Для массовой эксплуатации декодирование следует вынести из основного серверного потока. Снимок единого чек-листа фиксируется при старте обхода. Часы сервера определяют время; интерфейс показывает его в часовом поясе устройства.

Защита после отправки действует на уровне API и базы. Владелец серверных файлов обладает административным доступом, поэтому это не внешняя заверенная система аудита. Приложение не предоставляет галерею, но криптографическое доказательство происхождения кадра с камеры не реализовано.

Для первого пилота уже заданы «Свердлова» и Андрей. Далее: персональные аккаунты вместо демо, HTTPS-размещение, резервные копии и проверка PWA на рабочих телефонах. Публикация в магазинах и подписанные мобильные сборки для выбранного веб-варианта не требуются. Расписание периодичности, напоминания, задачи по нарушениям, внесение исправлений с журналом — последующие функции; правила для них пока не согласованы.
